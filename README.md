## セットアップ

```bash
npm install
npm run dev        # http://localhost:5173 でブラウザ起動
```

タイトル画面でモードを選択 →「1人で飛ぶ（練習）」または「ローカル2人対戦」。
試合中はクリックでマウスカーソルをロック、`Esc` で解除。

| 操作 | キーボード＋マウス | ゲームパッド |
|---|---|---|
| 前後左右移動 | `W` / `A` / `S` / `D` | 左スティック |
| 上昇 / 下降 | `Space` / `Ctrl` | RB / LB |
| 視点・照準 | マウス | 右スティック |
| 射撃 | 左クリック | RT |
| ブースト | `Shift` | LT |
| アイテム 1・2・3 | `1` / `2` / `3` | A / B / X |
| ダッシュ | `Shift` または**方向キー2回連打** | LT |
| 視点切り替え（三人称／一人称） | `V` | — |

ローカル2人対戦は上下2分割。ゲームパッド側にだけ弱いエイムアシストが入る（`config.input.aimAssistEnabled` でOFFにできる）。

タイトル画面からCPU対戦（鬼側/逃亡者側を選択）、CPU同士の観戦、ローカル2人対戦、1人練習が選べる。CPU難易度は Easy / Normal / Hard。

URLパラメータ：`?seed=42`（乱数シード）、`?map=generated`（シードから都市を自動生成）。

## 光線銃（投射体）

銃はヒットスキャンではなく**弾速のある投射体（ボルト）**を撃つ。トリガーを引くと `src/sim/weapon.ts` がボルトを1発生成し、`src/sim/projectile.ts` が毎ティック前進させて、最初に当たったもの（機体か地形か）で止める。届くまでに時間がかかるので、**距離が精度のコストになる**。

- ボルトは毎ティック「掃引」して当たり判定を取る。185 m/s なら1ティックで3m進み、これは機体の幅より広いので、終点だけを調べる実装では機体をすり抜けてしまう。
- 射程は `range / projectileSpeed` 秒の寿命として表現され、最大射程ちょうどで消える。
- 撃った本人には当たらない。ボルトは機体の速度を継承しない（照準の向きがそのまま弾道になる）。
- ボルトはワールドの状態（`world.projectiles`）なので、スナップショットにも入るしリプレイも正確。描画は毎フレーム実際のボルトを補間して描く。

この変更でCPUの**偏差射撃が本物になった**。`src/ai/tactics.ts` の `interceptTime()` が「ボルトが届く時刻に相手がどこにいるか」を二次方程式で解き、難易度の `leadAccuracy` がその補正をどれだけ適用するかを決める。弱いCPUは横切る相手の後ろに撃ち、強いCPUは当てる。逃亡者は射線に入ると左右に振って（`ai.jinkAmplitude` / `jinkRate`）狙いを外させる — ヒットスキャンでは無意味だった動き。

## アイテム

両陣営が3種類ずつ消耗品を持つ。すべて `src/sim/items.ts`、数値は `config.items`。**2つのキットは対になっている**：逃亡者の3つは鬼から情報か時間を奪う道具、鬼の3つはそれを取り返す道具。

### 逃亡者

| アイテム | キー | 効果 | 所持 / クールダウン |
|---|---|---|---|
| デコイ | `1` / A | 自機と同じ見た目の分身を、そのときの速度で飛ばす | 2回 / 12秒 |
| フラッシュ | `2` / B | 0.9秒後に炸裂。半径45m・視線が通る相手を2.2秒目潰し | 2回 / 14秒 |
| オーバーチャージ | `3` / X | 2.5秒間、射撃が弾を消費しない | 1回 / 20秒 |

### 鬼

| アイテム | キー | 効果 | 所持 / クールダウン | 何に効くか |
|---|---|---|---|---|
| スキャン | `1` / A | 2.5秒間、半径120m以内の本体を計器で捕捉する | 1回 / 15秒 | デコイ・フラッシュ・遮蔽 |
| スネア | `2` / B | 投げて炸裂。半径22m・視線が通る相手の最高速度を3秒間 55% に落とす | 1回 / 18秒 | 逃げ足 |
| オーバーチャージ | `3` / X | 2.5秒間、射撃が弾を消費しない | 1回 / 20秒 | 弾切れ |

**シールド**（ダメージ肩代わり）と**オーバードライブ**（速度×1.18・ブースト無消費）も実装済みだが、いまは枠から外れている。`items.loadout` で入れ替えられる。外した理由は測定で、弾が希少になるとシールドは守る対象のダメージ自体が減って価値が落ち、鬼はもともと詰めざるを得ないのでオーバードライブが要らない。スネアの代わりにオーバードライブを入れた構成は 41.7%・タッチ28.3% で、スネア構成の 50.0%・タッチ33.3% に負けた。

- **デコイ**は投げた瞬間の速度を引き継いで飛ぶ。これが肝で、鬼が追っていた進路をそのまま分身が続けるので、同じ瞬間に本体が別方向へ抜けると入れ替わる。CPUの `Perception` は機体と分身を区別できず、**直前に追っていた接触に一番近いものを追い続ける**（`tests/items.test.ts` で検証）。撃てば消えるので、鬼は弾を1発使って正体を確かめられる。
- **シールド**は時間ではなく吸収量で壊れる。時間だけだと「出したら撃ち合いを無視する」が正解になってしまうため。衝突ダメージは防げない（飛び方が雑な代償はアイテムで消せない）。
- **フラッシュ**は自分は絶対に目潰しされず、遮蔽の陰に入っていれば効かない。CPUに当たると `Perception` が完全に止まり、最終目撃からの経過時間だけが進む。人間に当たると画面が白く飛ぶ。

鬼側の3つは、どれも撃墜ではなく**タッチ**を狙う道具にしてある。

- **スキャン**は視野角も遮蔽も無視して本体だけを返す。デコイを追っていても本物に切り替わり、フラッシュで目潰しされていても効く。効かないのは**距離**だけ（120m超は圏外）で、これが「本当に引き離した逃亡者は見つからない」を残している。CPUは `Perception`、人間はレーダーが同じ規則で動く。
- **スネア**はフラッシュと同じ形（投擲・炸裂半径・視線判定）にしてある。読み方が同じになるので、遮蔽の陰に入れば効かないことが直感で分かる。加速度ではなく最高速度を削るので、操作感は変わらず「振り切れるかどうか」だけが変わる。
- **オーバードライブ**はゲージを消費しないのが本体。速度上昇そのものより「追跡中にゲージが切れない」ほうが効く。スネアと同時にかかると掛け算になるので、相殺して中間の速度になる。

**オーバーチャージ**は弾数上限があって初めて意味を持つ道具。ただし**長いと弾数上限そのものを無効化する**：最初5秒で試したところ、鬼の弾切れ率が80%→50%に落ち、タッチ勝ちが31.7%→16.7%に半減した。2.5秒は「撃ち直せる」ではなく「一連射だけ通る」長さ。

アイテムはすべてスナップショットに含まれるので、リプレイと決定性は維持されている。デコイは人間の鬼に対しても効く：レーダーは**実機もデコイも区別なく赤い点**として出すので、画面を見て本物を見分けることはできない（`radarBlips` / `tests/items.test.ts`）。ただしスキャン中だけは例外で、**本物1点だけ**が遮蔽越しに出る。

### アイテムが何を変えたか

同じ弾速（65/58）でアイテムの有無だけを比べた測定：

| | アイテムなし | アイテムあり |
|---|---|---|
| 鬼の勝率（Easy） | 47.5% | 33.3% |
| **時間切れ勝ち** | **20.0%** | **40.0%** |
| 平均ラウンド長 | 83.6秒 | 120.8秒 |

勝率が動いただけではなく、**決着のつき方が変わった**のが重要。それまで時間切れ勝ちは全体の3〜20%しかなく、「逃亡者は逃げ切れないので鬼を撃墜するしかない」状態だった。アイテムで視線を切れるようになって初めて、設計書が想定していた「逃げ切って勝つ」が成立している。

副作用として弾速を上げ直せた。アイテムなしでバランスを取るには弾速65（ブースト中の機体の1.3倍＝自分の弾に追いつきそう）まで落とす必要があったが、アイテムありなら90前後（約2倍）で釣り合う。

## レーダー（HUD）

画面右上の円形レーダー。方向矢印を置き換えたもので、方向だけでなく距離と高度差も読める。

- **自機が中心**、レーダーの上＝自分が向いている方向（機首基準で回転する）
- **接触は赤い点**。実機もデコイも同じ点として出るので、**デコイを使われると点が増える**。どれが本物かは画面からは分からない
- 例外は**スキャン中**。レーダーの枠が緑に光り、範囲内なら本物1点だけが遮蔽越しに出る（圏外なら普通の表示に戻る）
- 内側の輪は射程の半分。近い接触は点が明るくなる
- 点の上に黄色い線＝自分より高い、下に水色の線＝自分より低い（差が `hud.radarAltitudeBand` 以上のとき）
- 範囲は `hud.radarRange`（200m）。外の相手は**そもそも映らない**ので、レーダーには本当の限界がある
- 表示条件は `hud.enemyIndicator` のまま：`lineOfSight`（既定・視線が通るときだけ）/ `always` / `never`

判定ロジックは `radarBlips()` という純粋関数に切り出してあり、DOMなしでテストできる。

## 操作と手触り

実際にプレイしてもらったフィードバックで直した点。**「視点変更がやりにくい」「急旋回ができない」「のっぺりしている」「高低差が分かりにくくて障害物に引っかかる」**は、どれも別々の問題ではなく、CPU同士の対戦では絶対に表面化しない種類の問題だった（CPUは `AiController` が自分で照準を持つので、カメラ操作を一切しない）。

| 症状 | 原因 | 直し方 |
|---|---|---|
| 急旋回ができない | `mouseSensitivity` 0.0022 rad/px = **180°振り向くのにマウス移動1430px**。普通のFPSは400〜600px | 0.0052 に（約610px） |
| 動きがのっぺり | 機体が**バンク（旋回時の傾き）しない**。平行移動とヨーだけ | カメラと機体の両方を旋回速度に応じてロール。描画のみで、当たり判定も物理も変えない |
| スピード感がない | ブーストしても画面が変わらない | ブースト中はFOVを+11°。速度は「見える」ようにしないと感じられない |
| 高低差が分からない／引っかかる | 三人称視点に**地面との位置関係を示すものが何もない** | 真下の地面にリング＋そこまでの垂直線。高度に応じてリングが広がって薄くなる |
| 三人称だと近くが見づらい | 視点が機体の後ろにあるので、機体越しに手前を見ることになる | **`V` キーで一人称視点に切り替え**。コックピットからは見えているものが当たるものと一致する |
| Shift加速が押しにくい | 移動と加速が別の指 | **方向キーの2回連打でもダッシュ**（Shiftも従来どおり有効）。押しっぱなしの間は続き、離すと解除 |

一人称視点はカメラの追従を3倍速くしてある。機体とカメラの間にラグがあると、三人称では「重み」に見えるものが一人称では酔いになるため。

## 雲

高度80m以上はほぼ空っぽの空だった（マップの障害物122個のうち100個が下から25mに集中）。銃があるうちは遠距離で撃ち合えるので問題にならなかったが、上空へ逃げた逃亡者には使えるものが何もなく、速いほうが勝つだけの空間になっていた。

**雲は視線だけを遮り、移動は遮らない。** `CloudVolume`（球）として `maps/*.json` に書き、Rapierのワールドには一切入れない：

- 機体も弾もグレネードも**そのまま通り抜ける**。高高度に墜落の危険を増やさずに隠れ場所を作れる
- `PhysicsWorld.isBlocked` だけが雲を見る。CPUの `Perception`、レーダー、射線判定、フラッシュ／スネアの炸裂判定がすべて同じ規則で従う
- 判定は線分と球の解析的な交差（`segmentHitsSphere`）なのでコライダー不要

city01 には10クラスタ36個を高度70〜145mに配置した。効果は時間切れ勝ちが31.7%→38.3%、平均ラウンド長が103秒→104秒。

**AIに雲を「目指させる」のは失敗だった。** 雲の中心を `coverHotspots` に入れてみたところ、CPUが上空の雲に籠もって Normal が33.3%（時間切れ53.3%・タッチ10.0%）になった。雲は**追跡の途中でたまたま視線が切れる場所**であって、目的地ではない。この変更は入れていない（`src/maps/types.ts` に経緯を残した）。

## ルールとバランス

- **鬼（ハンター）**：逃亡者のHPを0にするか、タッチすれば勝ち。移動速度・ブースト速度・光線銃のダメージ・射程・弾速・連射速度・弾数すべてで逃亡者を上回る。ダメージは9（逃亡者8）だが連射が速いぶんDPSでは約1.4倍。
- **弾数は1ラウンド32発（逃亡者28発）でリロードなし。** これが「鬼ごっこ」を成立させている中心の仕組み。下の「弾数上限がすべてを変えた」を参照。
- **逃亡者（ランナー）**：鬼のHPを0にするか、**制限時間（180秒）まで生き残れば勝ち**。火力と最高速では劣るが、ブーストゲージの消費が少なく回復が速いので、遮蔽物を使って視線を切り続けられる。アイテムの所持回数も鬼の倍（2回 対 1回）。
- 2ラウンド先取（Best of 3）。ラウンドごとに鬼と逃亡者が入れ替わるため、スコアは陣営ではなくプレイヤー枠ごとに記録される。
- 時間切れの扱いは `config.rules.timeoutWinner`（`"runner"` / `"draw"`）で切り替え。
- 数値はすべて `src/sim/config.ts` にある。この非対称バランスはまだ実戦検証していないので、フェーズ4の `simBatch` で鬼の勝率が45〜55%に入るか確認して調整するのが前提。主な調整つまみは `rules.timeLimit` と両陣営の `boostDrain` / `boostRegen`。

## マップ

マップは `maps/*.json`。`src/maps/loader.ts` が読み込み時に検証し、地形定義を高さフィールドに、トンネル定義をただの箱に展開する。物理と描画はどちらも同じ `Terrain` インスタンスを見るので、見た目と当たり判定が食い違うことはない。

```jsonc
{
  "id": "city01",
  "size": { "x": 400, "z": 400 },
  "ceiling": 150,
  "floor": 0,
  // 地形の起伏。seed から生成するか、heights に 0..1 を (resolution+1)^2 個直接書く
  "terrain": { "resolution": 32, "maxHeight": 20, "seed": 4021, "featureSize": 9, "octaves": 4 },
  // 覆われた通路。読み込み時に壁2枚＋屋根の箱に展開される
  "tunnels": [{ "pos": { "x": 0, "y": 8, "z": 0 }, "length": 150, "width": 18, "height": 13 }],
  "spawns": [{ "x": -170, "y": 55, "z": -170 }],
  "solids": [
    { "shape": "box", "pos": {...}, "size": {...}, "rotY": 0, "tag": "building" },
    { "shape": "cylinder", "pos": {...}, "radius": 3, "height": 5, "tag": "tree" }
  ]
}
```

`tag` は色分けと（フェーズ4以降の）AIの遮蔽物判定に使う：`building` / `bridge` / `tunnel` / `tree` / `crane` / `floater` / `prop` / `terrain` / `ground`。

`city01` の配置は `tools/buildCity01.ts` が生成している。建物のY座標を地形の高さから計算しているので、斜面に浮いたり埋まったりしない。地形パラメータを変えたら再生成する：

```bash
npx tsx tools/buildCity01.ts > maps/city01.json
```

シードからの自動生成は `generateCityMap(seed)`。地形・低層ビル・木々・トンネル・高架橋・高層ビル・渡り廊下・クレーン・浮遊物を3層すべてに配置する。ブラウザでは `?map=generated&seed=123` で遊べる。

## CPU（フェーズ4・段階A）

`src/ai/` はルールベースAI。人間と同じ `PlayerInput` を返すだけなので、シミュレーションからは人間と区別がつかない。

- **ナビゲーション**：マップを4mボクセルに分割（`nav/voxelGrid.ts`）し、3D A*（`nav/pathfind.ts`）で経路を出して平滑化する。ただし大半のティックでは経路探索は走らない — 目標までの直線が空いていればそのまま飛ぶ（`nav/navigator.ts`）。再探索は0.5秒間隔か目標が大きく動いたときだけ。
- **知覚**（`perception.ts`）：前方120°・視線が通る・視認距離190m以内のときだけ「見えている」。難易度ごとの反応時間を過ぎて初めて行動に反映される。見失ったら最終目撃位置と速度を覚えていて、8秒かけて忘れる。壁の向こうは見えない。
- **行動**（`behavior/`）：各行動をスコア化して最大を選ぶユーティリティAI。鬼は 追跡 / 射撃戦 / 捜索 / 待ち伏せ、逃亡者は 退避 / 隠れる / 反撃 / 引き撃ち。
- **難易度**：反応時間・照準の誤差・偏差射撃の精度・トリガー規律で調整（`config.ai.difficulty`）。

AIは `Math.random()` を使わずシード付きRNGで動くので、同じシードなら同じ試合になる（`tests/ai.test.ts` で検証）。

## バランス調整（simBatch）

```bash
npm run sim:batch -- --matches 500 --map city01 --hunter hard --runner hard
npm run sim:batch -- --matches 40 --time-limit 90 --set loadout.hunter.damage=9   # 値を振って試す
```

勝率・決着のつき方（撃墜/タッチ/時間切れ）・平均ラウンド長・命中率を出力する。`--set` は `config.ts` を書き換えずに1つの数値を上書きするので、DESIGN.md 9 の調整ループをそのまま回せる。

### 測定値（city01・制限時間180秒）

鬼の勝率の推移（同難易度同士）：

| 難易度 | ①ヒットスキャン | ②投射体・アイテムなし | ③逃亡者のみアイテム | ④両陣営アイテム | ⑤弾数上限 | ⑥雲＋オーバーチャージ | ⑦**出荷値**：弾数60/52 |
|---|---|---|---|---|---|---|---|
| Easy | 86.7% | 47.5% | 51.7% | 43.3% | 51.7% | 40.0% | **45.0%** |
| Normal | 96.7% | 45.0% | 41.7% | 51.7% | 45.0% | 50.0% | **41.7%** |
| Hard | 96.7% | 52.5% | 65.0% | 63.3% | 51.7% | 53.3% | **65.0%** |
| 平均 | 93.4% | 48.3% | 52.8% | 52.8% | **49.5%** | 47.8% | **50.6%** |

③〜⑦とも60ラウンド計測。⑤で初めて**平均だけでなく全難易度が個別に目標帯（45〜55%）に入った**。④までは Hard が 63〜65% で常に外れていたが、弾数上限で Hard の撃ち合い優位が頭打ちになった。

⑦（出荷値）は**プレイテストの指摘で弾数を人間向けに増やしたもの**。平均は帯内だが Hard が 65.0% に戻っている ── 弾が余るほどあれば命中率の高い難易度ほど有利になるので、⑤で消えていた Hard の外れが復活した形。代償の詳細は下の「弾数を増やした代償」を参照。**対CPUのバランスを取り戻すか、対人の手触りを取るかのトレードオフで、いまは後者を選んでいる。**

②で目標帯には入っていたが、弾速65はブースト中の機体の1.3倍しかなく「自分の弾に追いつきそう」な速度だった。③はアイテムで逃亡者に生存手段を与えたぶん、弾速を95（約2倍）まで戻したうえで釣り合っている。

### 鬼のアイテムが何を変えたか（すべて60ラウンド・Normal）

鬼のキットを設計どおり（所持2回ずつ・スキャン半径170m・オーバードライブ×1.25）入れると、**鬼が勝ちすぎた**：

| | 鬼の勝率 | タッチ | 時間切れ | 平均ラウンド長 |
|---|---|---|---|---|
| ③逃亡者のみアイテム | 41.7% | 10.0% | 23.3% | 87.2秒 |
| 鬼キット（初版） | **68.3%** | 5.0% | 5.0% | 52.6秒 |
| ④出荷値 | 51.7% | 5.0% | 5.0% | 56.5秒 |

どのアイテムが効いているかを1つずつ外して測った（Normal・40ラウンド、基準70.0%）：

| 外したもの | 鬼の勝率 | タッチ | 時間切れ |
|---|---|---|---|
| オーバードライブ | **50.0%** | 0.0% | 2.5% |
| スキャン | 57.5% | 7.5% | **15.0%** |
| スネア | 65.0% | 2.5% | 0.0% |

**オーバードライブが最大のつまみ**（−20ポイント）で、同時に**タッチ勝ちを生んでいるのもこれ**（外すとタッチが0%になる）。**スキャンは時間切れ勝ちを殺している**（外すと15%に戻る）— 逃亡者のキットが稼いでいた「視線を切って逃げ切る」を、そのまま打ち消すため。

出荷値は所持回数を全部1回に落とし（68.3% → 63.3%）、スキャンを半径120m・2.5秒に縮め、オーバードライブを×1.18にし、そのうえで**鬼のダメージを12→9に下げて**帯に戻した。ダメージを下げたのは、鬼がもう「距離を詰める道具」を持っているから銃だけで決着をつける必要がなくなったため。なお**ダメージはアイテム導入前には効かないつまみだった**（12→10→8→6でほぼ横ばい）が、両キットが入った今は効く。

アイテムの使用回数（1ラウンドあたり、Normal・出荷値）：デコイ 1.63 / シールド 0.85 / フラッシュ 0.55 / オーバードライブ 1.00 / スネア 0.97 / スキャン 0.77。鬼の3つは所持1回なのでほぼ毎ラウンド使い切っている。CPUは6種とも実際に使いこなしている。

### 弾数上限がすべてを変えた

**このプロジェクトで最大の変更。** それまで撃墜が決着の78〜90%を占めていて、「空中鬼ごっこ」なのにタッチ勝ちが5〜7%しかなかった。原因は2つあった：

1. **動機**：鬼は撃てば勝てるので、詰める理由がない
2. **機会**：`touchRadius` が 1.8m。機体半径が1.2mずつなので、ほぼ重ならないと成立しない

弾数上限（1ラウンド32/28発・リロードなし）が①を、`touchRadius` 4m が②を潰した。**両方必要**で、片方だけでは効かない。

| 設定 | 鬼の勝率 | 撃墜 | タッチ | 時間切れ | 平均長 |
|---|---|---|---|---|---|
| 弾数無制限・touch 1.8m | 51.7% | 90.0% | 5.0% | 5.0% | 57秒 |
| 弾数無制限・touch 6m | 51.7% | 83.3% | 11.7% | 5.0% | 56秒 |
| 弾70/60・touch 1.8m | 40.0% | 76.7% | 11.7% | 11.7% | 66秒 |
| 弾40/35・touch 6m | 46.7% | 56.7% | 31.7% | 11.7% | 67秒 |
| **弾32/28・touch 4m（出荷値）** | **45.0%** | **30.0%** | **38.3%** | **31.7%** | **103秒** |

面白いのは**弾を絞るほど鬼の勝率が上がる**こと（40.0% → 46.7%）。逃亡者の勝ち筋も撃墜だったので、弾を取り上げると逃亡者のほうが先に困る。だから**両陣営に上限をかけるのが正解**で、鬼だけに課すと鬼が弱くなるだけだった。

また `touchRadius` は単独では**勝率を1ポイントも動かさない**（1.8m/4m/6m/10m すべて51.7%）。決着の種類だけを変える純粋なつまみで、これは調整上とても扱いやすい。

### 弾数を増やした代償（プレイテスト後・60ラウンド）

実際に人間がプレイして「弾数は増やしていい、人間の照準はどうしても合わないから」という指摘を受けて 32/28 → **60/52** に増やした。代償は実測で出ていて、隠す意味がないので載せる：

| 弾数 | Easy | Normal | Hard | 平均 | タッチ勝ち平均 | 撃墜平均 |
|---|---|---|---|---|---|---|
| 32/28 | 40.0% | 50.0% | 53.3% | 47.8% | **27.2%** | 35.6% |
| 45/40 | 41.7% | 40.0% | 60.0% | 47.2% | 19.4% | 60.5% |
| **60/52（出荷値）** | 45.0% | 41.7% | 65.0% | **50.6%** | 18.9% | **63.9%** |

**劣化のほとんどは 32→45 で起きていて、45→60 の追加コストはほとんどない**（タッチ 19.4% → 18.9%）。増やすと決めたなら 60 まで行っても大差ない、という形をしている。

勝率の平均は帯内（45〜55%）に残っているが、**決着の質は撃ち合い寄りに戻った**。弾数上限で 35.6% まで落としていた撃墜が 63.9% に戻り、タッチ勝ちは 27.2% → 18.9%。特に **Hard では鬼の弾切れが2%しか起きない**（命中率35%だと60発は余る）ので、Hardに限っては上限がほぼ無効になっている。

これは想定済みのトレードオフで、戻し方は弾数を絞ることではなく**武器の種類を増やすこと**（弾数の少ない高威力武器、連射武器、など）だと考えている。未着手。

### 決着のつき方（出荷値・60ラウンド）

| 難易度 | 撃墜 | タッチ | 時間切れ | 平均ラウンド長 | 鬼が弾切れ |
|---|---|---|---|---|---|
| Easy | 40.0% | **36.7%** | 23.3% | 93.4秒 | 67% |
| Normal | 68.3% | 13.3% | 18.3% | 71.6秒 | 38% |
| Hard | 83.3% | 6.7% | 10.0% | 53.3秒 | 2% |

弾数上限を入れた時点ではタッチ勝ちが平均 6.1% → 27.2%、撃墜が 78.3% → 35.6% まで動いていた。**人間向けに弾数を増やした結果、その半分を手放している**（上の表を参照）。Easy では依然タッチが36.7%で主役だが、Normal/Hard は撃ち合いが主体に戻っている。

難易度が上がるほど撃ち合いの比重が戻るのは、命中率が高いほど弾数上限が効かなくなるため。構造的なもので、弾数だけで両立はできない。

### 弾速と勝率の関係（アイテム導入前・30ラウンド）

アイテムを入れる前は、**弾速が唯一の効くつまみだった。**

| 弾速（鬼/逃亡者） | Easy | Normal | Hard | 平均 |
|---|---|---|---|---|
| 185 / 165 | 66.7% | 90.0% | 93.3% | 83.3% |
| 90 / 81 | 73.3% | 60.0% | 66.7% | 66.7% |
| 75 / 68 | 56.7% | 60.0% | 73.3% | 63.3% |
| 65 / 58 | 47.5% | 45.0% | 52.5% | 48.3% |
| 60 / 54 | 43.3% | 40.0% | 56.7% | 46.7% |

### 効かなかったつまみ（すべて実測）

| 振った値 | 結果 |
|---|---|
| ダメージ 12→10→8→6 | 70% → 73% → 67% → ほぼ横ばい |
| 制限時間 180→120→90→60秒 | 67% → 67% → 63% → 63% |
| CPUの視認距離 190→140→100m | 70% → 80% → 73%（**逆に悪化**） |
| 回避の振り幅 26→45→70m | 70% → 80% → 90%（**逆に悪化**） |
| 鬼の巡航速度 25→23 m/s | 67% → 80%（**逆に悪化**） |
| 命中半径 1.8→1.4→1.1m | 80% → 73% → 80%（誤差の範囲） |

逆効果になるものが多いのは、**逃亡者の勝ちの大半が「逃げ切り」ではなく「鬼を撃墜すること」**だから。銃を弱くしたり、視認距離を縮めたり、鬼を遅くして交戦時間を伸ばしたりすると、逃亡者は唯一の勝ち筋を失う。時間切れ勝ちは今でも全体の 3〜13% しかない。

つまり構造的な問題は「鬼が全項目で上回る」ことそのものではなく、**逃亡者が180秒逃げ切れないこと**にある。逃げ切りを成立させるには、遮蔽をもっと増やしたマップか、逃亡者専用の離脱手段（短距離ワープ、ステルス、囮）が要る。数値調整だけでは届かない。

### 出荷値についての注意

数値はすべて**AI同士**の対戦。人間の逃亡者はCPUほど撃ち合いに付き合わないはずなので、実際の対人バランスは別に測る必要がある。

弾速の細かい値は**30ラウンドでは区別がつかない**（標準誤差±9%程度あり、弾速90・97・105の間で同じ難易度が20ポイント振れた）。出荷値95は90〜105という「差が測れない帯」の中間を取っただけで、データが一意に選んだ値ではない。

### 銃なし（純粋な鬼ごっこ）を検討した結果

弾数を0にすれば銃なし版がそのまま測れるので、実測した（Normal・60ラウンド）:

| 試した設定 | 鬼の勝率 |
|---|---|
| そのまま銃だけ無くす | 76.7% |
| 速度を完全対称に | 90.0%（悪化） |
| 逃亡者のほうを速く | 70.0%（唯一マシ） |
| 逃亡者の旋回性能を上げる | 86.7%（悪化） |
| 両者の旋回性能を下げる | 96.7%（悪化） |
| 雲を追加してから | 78.3%（ほぼ不変） |

**何をいじっても改善しない。** 一番マシで70%で、目標帯に遠い。外れた仮説から分かったことのほうが重要だった：

- 旋回性能を**下げる**と鬼が有利になる。追う側は機首を向けるだけでよく、旋回性能を必要としているのは逃げる側だから
- では逃亡者の旋回性能を**上げれば**いいかというと、これも悪化する

2つ目が本質で、**`runnerBrain` には「かわす」挙動がない**。`evade`/`hide` は「遮蔽へ飛ぶ／離れる方向へ飛ぶ」だけで、接触寸前の回避をしない。銃ありなら視線さえ切れば勝てるので不要だった挙動だが、鬼ごっこではそれが全て。**つまり上の数値は銃なし版を不当に低く見せている** — 人間が逃亡者ならもっと良いはずで、CPU同士の測定では判定できない。

銃なしを本気でやるなら、数値ではなく (1) 回避挙動の実装、(2) アイテムの作り直し（ダメージがないのでオーバーチャージが無意味になる）の2つが先。

残っている課題：

- **CPUは弾の使い方が下手**。`canShoot` は「撃てるなら撃つ」ままで、残弾を見て「この距離では撃たない」という判断をしていない。人間なら当然やる温存が、CPUにはない
- **`runnerBrain` に回避挙動がない**（上記）。銃ありの現状でもタッチ勝ちの質に効くはず
- **Hard の撃墜58.3%** が他の難易度から浮いている。難易度別に弾数を変えるかは未検討
- 数値は全部AI同士。人間の逃亡者はCPUほど撃ち合いに付き合わないはずなので、対人バランスは別に測る必要がある

計測の精度についても引き続き注意が要る。40〜60ラウンドの標準誤差は6〜8ポイントあり、**単独では有意差と言えない振れ幅**（5〜10ポイント）をいくつも見ている。はっきり読めたのは効果量の大きいものだけ：弾数上限＋`touchRadius`（タッチ勝ち +29ポイント）、所持2回の鬼キット（+27ポイント）、オーバードライブ（−20ポイント）、銃なし（+27ポイント）、雲をAIの目的地にする（−17ポイント）。

弾速を別の値で試すのは1行：

```bash
npm run sim:batch -- --matches 40 --set loadout.hunter.projectileSpeed=130 --set loadout.runner.projectileSpeed=117
```

## 学習AI（フェーズ5・段階B）

DESIGN.md 7.2 のプレイヤーモデル。機械学習は使わず、小さな配列の統計だけ。`src/ai/learning/` にあり、`src/sim/` には一切触らない。

- **マップ別・プレイヤー別**に保存（ブラウザは IndexedDB、Node とテストはメモリ）
- 1ラウンドごとに 0.95 倍に**減衰**するので、癖が変わればついていく
- タイトル画面に**リセットボタン**、リザルト画面に「CPUが見ているあなたの癖」
- `npm run sim:learn` で効果を測定できる

### 鉄則：見えたものしか記録しない

CPUは壁越しに相手を見ない（DESIGN.md 7.1）。モデルへの入力も同じで、`perception.visible` が立っている間だけ記録する。真の位置を毎tick流し込めば「隠れている場所」を学習できてしまうが、それは壁越しに見ているのと同じこと。

### 位置の学習はうまくいかなかった（構造的な理由で）

DESIGN.md 7.2 は「よく居る場所」「移動ルートの癖」を挙げているが、**これらは原理的に偏って学習される**。実測：

| | 上位エリア |
|---|---|
| 逃亡者が**実際に**いる場所 | (-150,38,150) (150,38,-150) (50,38,-150) (-150,38,-50) |
| 鬼が**見た**場所 | (50,38,150) (-150,38,150) (50,38,50) (-50,38,-150) |

**鬼が逃亡者を見えているのは1ラウンドの28%しかない。** 目撃とは「相手が隠れていなかった瞬間」なので、目撃から作った分布は「どこに隠れるか」ではなく「どこで見つかるか」になる。さらに「見失ったあとどこで再発見するか」は**鬼がどこを探したか**の記録でもあるので、それに従って探すと鬼は自分がいつも探す場所を探し続ける。

実測でも捜索は**悪化**した（3.93秒 → 6.07秒）。なので位置系の統計は**記録も表示もするが、行動には使っていない**（`src/ai/tactics.ts` の `searchPoint` に経緯を残した）。表示では「どこで見つかりやすいか」という、実際に測れているとおりの名前にしてある。

### 偏差射撃の補正は「はっきりした癖」にだけ効く

回避方向（左右）は目撃バイアスがかからない統計なので、これは使っている。ただし**当初の実装は鬼の命中率を半減させた**（Hard 32.4% → 16.6%）。原因は3つあり、全部直した：

| 問題 | 直し方 |
|---|---|
| 上下も「回避」として数えていた | 0.35秒の窓では上下方向の主成分は回避ではなく**遮蔽のある低空へ降りる移動**。左右だけにした |
| 補正量が過大（Hard で約17m、当たり判定は1.8m） | 速度×リード時間は**すでに適用済みのリードの二重計上**。回避の振り幅（`jinkAmplitude`）基準に変えた |
| 少ないサンプルで極端な偏りが出る | 8対4で偏り0.33になってしまうので、`total + MIN_SAMPLES` で割って**ゼロに縮める**推定に変えた |

そのうえで **偏り 0.25 以上でなければ補正しない**。「そこそこ偏っている」程度の相手に補正をかけると、もともと当てている鬼の弾が外れるだけだから。現在はこのゲートで**学習あり／なしがビット単位で同一**（Hard 32.4% で一致）＝ 退行はゼロ。

### 受け入れ条件は達成していない

DESIGN.md 9 の条件は「同じプレイヤーと数戦すると捜索と偏差射撃の精度が上がる」だが、**CPU相手には上がらない**。理由は単純で、**CPUの逃亡者には癖がない**。回避は対称なサイン波なので、`jinkBias 0.9` まで偏らせても検出される偏りは 0.02〜0.13 にしかならず、ゲートに届かない。

つまり「学習する仕組みは動いているが、学習すべき癖を持った相手がいない」状態。人間のプレイヤーは左右どちらかに偏るはずなので、**対人で測り直す必要がある**。仕組み自体は合成データでユニットテスト済み（`tests/learning.test.ts`）。

```bash
npm run sim:learn -- --matches 24 --hunter hard --runner hard --jink-bias 0.9
```

## 構成メモ

- `src/sim/` は **描画に一切依存しない**。Three.js も DOM も import しない。Node.js 上で単体実行でき、これがテスト・AI学習・将来のサーバー権威型オンライン対戦の土台になる。
- シミュレーションは固定60Hz。`World.step()` は同じ初期状態・同じ入力列・同じシードなら必ず同じ結果になる（`tests/world.test.ts` で検証している）。
- 乱数は `src/sim/rng.ts` のシード付きRNGのみ。`Math.random()` は使わない。
- `src/sim/rules.ts` は `World` に依存しない純粋な関数群なので、手で組み立てた状態だけでラウンドの勝敗をテストできる。
- HPの増減はすべて `src/sim/damage.ts` を通る（無敵時間・撃墜処理・イベント発行が一箇所にまとまる）。
- 人間・ゲームパッド・AIはすべて同じ `PlayerInput` を `world.step()` に渡す。`src/ai/controller.ts` は `InputSource` を実装しているだけで、シミュレーション側にAI用の分岐は一切ない。エイムアシストも入力側で完結している。
- 描画側（`src/render/`）は `World` の状態を読んで補間するだけで、状態を書き換えない。
